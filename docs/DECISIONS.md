# Decisions

SPEC section 6 holds the main decisions (D1–D11). This file records every further decision taken during the build, with the reason.

| ID | Decision | Reason |
| --- | --- | --- |
| D-01 | Use the latest stable package versions at build time (Express 5.3, Mongoose 9, Zod 4, Vite 8, React 19, React Router 8, Tailwind 4, Socket.IO 4.8). | SPEC section 3. All share stable APIs with their previous majors for what we use. |
| D-02 | Tailwind v4 with CSS-first config: semantic tokens are CSS variables on `:root` / `.dark`, mapped into Tailwind with `@theme inline`; dark mode is a `.dark` class on `<html>` set before first paint. | One token source, no flash of the wrong theme, components never hard-code light/dark colours. |
| D-03 | Campus centre `13.1718, 77.5362` (Presidency University, Itgalpura, Rajanukunte, Bengaluru). | Best available coordinates; **the user should confirm** and edit `CAMPUS_CENTER_LAT/LNG` in `server/.env` if needed. Only the seed data and map defaults depend on it. |
| D-04 | Flutter is not installed on the build machine, so the mobile app is hand-written: `lib/`, `test/`, `pubspec.yaml`, Android manifests and `MainActivity.kt` are committed; Gradle files and the wrapper are generated by `flutter create .` (documented). | `flutter create` cannot run here. Running it later fills only the missing files, so the committed customisations survive. |
| D-05 | Mobile fonts: static Plus Jakarta Sans TTFs (400/500/700/800) from the official tokotype repository, OFL licence included. | Flutter needs TTF/OTF; @fontsource only ships WOFF/WOFF2. |
| D-06 | Admin user management (`/api/users`) was built in phase 2 instead of phase 3. | Phase 2's "student on admin route → 403" check needs a real admin route. |
| D-07 | Reopening restarts the SLA clock: `slaStartedAt` = reopen time, `dueAt` recomputed, `escalatedAt` cleared. A severity change recomputes `dueAt` from `slaStartedAt`. | A reopened issue is new work; keeping the old deadline would make it instantly overdue and escalate twice for nothing. |
| D-08 | "Hours overdue" in the priority formula counts whole hours (floor). | Keeps priority an integer that changes once per hour, matching the hourly recompute job. |
| D-09 | When a report has both GPS and a scanned room, the room's point is stored. | D9: a room QR gives room-level accuracy indoors where GPS is unreliable. |
| D-10 | Smart assignment falls back to all active technicians (flagged `skillMatch: false`) when nobody has the category skill. | The admin is never left without a suggestion (e.g. category "other" with no specialist). |
| D-11 | Students never see another person's identity: supporters do not see the reporter, and staff entries in the history show only the role. Technicians see the reporter neither. | Minimal disclosure; nobody needs a reporter's name to fix a projector. Admins see everything. |
| D-12 | `clientRequestId` reused by a *different* user → 409 `DUPLICATE` instead of returning that user's issue. | Returning it would leak another student's report. |
| D-13 | CSV export: max 5000 rows, UTF-8 BOM, CRLF, and cells starting with = + − @ are prefixed with a quote. | Excel compatibility and protection against CSV formula injection. |
| D-14 | Day buckets for trends use the campus time zone (Asia/Kolkata). | "Resolved today" must match the wall clock at the booth, not UTC. |
| D-15 | Seed photos are original SVG scenes (one per category, broken and fixed states) rendered by sharp; seed randomness is deterministic. | No stock photos (SPEC 8.1); repeatable demos and screenshots. |
| D-16 | Web UI tests and screenshots run against an isolated seeded stack (`client/scripts/stack.mjs`: API :5055, DB `fixit_ui`, uploads `server/.cache/ui-uploads`, web :5174). | Repeatable runs that never touch the development database, uploads or ports. |
| D-17 | Map tiles: OpenStreetMap standard tiles; dark mode inverts them with a CSS filter. | No API key and no second tile provider (SPEC 3). |
| D-18 | Seeded resolved issues are kept inside the auto-close window (resolved < 72 h ago). | Otherwise the auto-close job closes them all at start-up and the demo loses its "confirm the fix" examples. |
| D-19 | Duplicate threshold `DUPLICATE_SIMILARITY = 0.88`, calibrated on the seed images (`npm run calibrate:ai -w server`, 42 photos, 6 variants × 7 categories): same-category pairs 0.904–0.991 (p5 0.940), different-category pairs 0.515–0.870 (p95 0.847). 0.88 sits between the worst same-category and best different-category pair. Zero-shot accuracy on the same set: 42/42. | SPEC D6. Real photos vary more than the illustrations; the threshold leaves margin on both sides and can be re-tuned in `.env`. |
| D-20 | CLIP via transformers.js with quantised (`q8`) weights; text prompts (4 phrasings × 7 categories) are embedded once at load and the text encoder is then released; one vision pass gives both the suggestion and the embedding. | ~90 MB download, ~6 s load, ~65 ms per photo on a laptop CPU; keeps memory low on the demo laptop. |
| D-21 | Duplicate candidates use the active statuses only (open, assigned, in progress, reopened), and exclude the caller's own reports. | "Me too" on a resolved issue makes no sense (the reporter confirms or reopens it); offering a student their own report as a duplicate is noise. |
| D-22 | Without an image embedding (AI off or the seed loaded without `--with-ai`), duplicates fall back to same-category issues nearby. Use `npm run seed:ai -w server` to store embeddings for the seed photos. | The feature keeps working (D6: AI failure never blocks), just less precisely. |
| D-23 | `npm run e2e` uses a deterministic fake AI taught the scenario photos; `E2E_REAL_AI=1` runs it with the real model (also passing). | SPEC D6: tests never download models; CI stays fast and offline-safe. |
| D-24 | `npm run screenshots` fails (exit 2) if any page is wider than its viewport. | Automates the "no overflow at 390 px" visual-QA rule; it caught two layout bugs. |
| D-25 | Category chart palette validated with the dataviz validator (lightness band, chroma floor, CVD and normal-vision separation, contrast) on `#FFFFFF` and `#131D36`: furniture `#B5651D`, other `#D6409F`, electrical `#E0A030` (light) / `#C0841C` (dark). Amber's light-mode contrast WARN is relieved by the always-visible legend with values. | The previous brown and gray failed the chroma floor (read as gray); dark mode needs its own step. |
| D-26 | Live Booth (`/live`) requires an admin session and shows only anonymous data; the visitor QR points to `/register` on the same origin. | The booth runs on the admin's laptop at the expo; nothing personal is ever on a public screen. |
| D-27 | Building health is shown as a bar + number + text band (Healthy ≥ 75, Needs care ≥ 50, At risk < 50). | Status-like colours never carry meaning alone. |
| D-28 | Mobile Firebase is initialised from `--dart-define` values (`FIREBASE_API_KEY`, `FIREBASE_APP_ID`, `FIREBASE_SENDER_ID`, `FIREBASE_PROJECT_ID`) instead of `google-services.json` + the Google Services Gradle plugin. | SPEC phase 10 requires the APK to build with and without Firebase files; the Gradle plugin fails without the JSON. Keys stay out of git. |
| D-29 | `flutter_local_notifications` dropped: foreground pushes are shown as in-app banners (and skipped while the socket is connected); background pushes are displayed by Android from the FCM notification payload. | One fewer native plugin; no duplicate notifications. |
| D-30 | Offline queue retries network errors, 5xx, 408, 429 and 401; other 4xx are final. Backoff 5 s × 2ⁿ, capped at 5 min; immediate flush on reconnect and sign-in; checked every 30 s. | Never lose a student's report to a temporary problem or an expired session; never retry something the server rejected for good. |
| D-31 | Biometric unlock is opt-in, enabled only after a successful check, locks on cold start and after 30 s in the background. | Avoids lock-outs; matches common banking-app behaviour without being annoying during short app switches. |
